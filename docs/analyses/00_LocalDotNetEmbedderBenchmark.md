# Local DotNet Embedder Benchmark

| Name | Models | Usages | Pros | Cons |
| --- | --- | --- | --- | --- |
| **SmartComponents.LocalEmbeddings** | all-MiniLM-L6-v2 (ONNX) and lightweight custom ONNX models. | - Semantic search in Blazor, WPF, WinForms, or Web API apps. - Rapid prototyping without setup. - Low-footprint vector storage. | - **Total plug-and-play** (automatic model downloading and management). - Native quantization (int8, bit1) reducing RAM usage by 4x to 32x. - Zero ONNX configuration required. | - Default model is fixed (all-MiniLM-L6-v2). - Less flexible for large or recent embedding models. |
| **ElBruno.LocalEmbeddings** | bge-micro-v2, Harrier (Microsoft), all-MiniLM-L6-v2, and pre-packaged Hugging Face ONNX models. | - Applications using the standard Microsoft.Extensions.AI abstractions. - Lightweight, multi-model RAG pipelines in C#. | - Implements the official .NET IEmbeddingGenerator interface. - Easy setup via Dependency Injection. - Good selection of modern pre-configured models. | - Relies on the package author to maintain and pre-configure models. |
| **Microsoft.ML.OnnxRuntime** | **Any ONNX model** (BGE-M3, Nomic-Embed, E5, gte-large, etc.). | - High-throughput, high-performance applications. - Systems requiring specific or proprietary models. - Hardware acceleration (GPU via CUDA, DirectML, OpenVINO). | - **Maximum performance** and full low-level control. - Comprehensive hardware support (DirectML, CUDA, TensorRT, etc.). - Compatible with any model exported to ONNX. | - Higher implementation complexity (text tokenization must be handled manually or via external C# tokenizer). - Lacks high-level abstractions. |
| **Microsoft.SemanticKernel** *(ONNX Connector)* | BERT and ONNX embedding models supported by the BertOnnx connector. | - Complex RAG applications or AI agents built on Semantic Kernel. - Seamless toggling between Local and Cloud execution (Azure OpenAI). | - Native integration with the Semantic Kernel ecosystem (Memory, Plugins, Vector Stores). - Enterprise-grade architecture standard for .NET. | - Heavier setup if you only need basic vector generation. - Local ONNX connector is less flexible than raw ONNX Runtime. |
| **LLamaSharp** | **All GGUF format models** (nomic-embed-text, bge-m3-gguf, mxbai-embed-large, etc.). | - Projects combining local LLMs and local GGUF embeddings. - Optimized RAM/VRAM resource usage without needing ONNX. | - Powered directly by native llama.cpp bindings (C++ DLLs). - Excellent memory management and quantization support (Q4, Q8). - Access to the vast GGUF model ecosystem. | - Native dependency management required per target OS (Windows/Linux/macOS). - Higher memory footprint compared to tiny dedicated ONNX models. |
